# Architecture
Independent native application, not an Electron port. Existing fork is reference/archive; do not modify upstream main or church-stable. Until an independent repository is created, keep planning documents on church-dev only.
Proposed C#/.NET 10 LTS, Avalonia UI, SQLite. Verify toolchain and dependency licenses before locking versions. Windows first, platform adapters for optional macOS. Native render surfaces with GPU composition; prototype Skia/Direct3D interoperability and hardware video decode (D3D11VA/Quick Sync); evaluate LibVLC/FFmpeg before selection. Share decoded background where feasible; pre-layout/cache lyrics; no synchronous I/O on live path. Separate editor/import jobs from output state; isolate renderer failure where feasible. Independent Main/Online/Stage output states with shared service cue state. Static Stage via DisplayLink. Remote ASP.NET Core/SignalR or WebSocket local server with authentication, rate limits and role-based commands. No cloud. YouTube optional isolated browser component started only when needed; verify embed policy and playback. LibreOffice worker for conversion/playback compatibility tests; cached PDF/image fallback. M1 remains independent broadcast engine; PTZ adapter directly controls K20UH via verified protocol. Protect secrets and personal church data from public repository. License review before reusing any FreeShow or converter source. No actual camera commands assumed valid until device tests.
